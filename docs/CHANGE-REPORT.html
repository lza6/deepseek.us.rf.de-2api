deepseek-es-2api · 变更报告

v0.4.0 → v0.9.0 · 6 个版本 · 135 单测 + 46 集成全绿 · 全部经真实 E2E 验证

一、背景与直觉

项目是什么：把 deepseek.es（WordPress + AIPKit 插件）包装成 OpenAI 兼容与 Anthropic 兼容的 Rust API 网关。内置 Cloudflare Turnstile 求解。

核心约束（决定了所有设计）：

  • 上游 不支持原生 function calling、图片、联网 —— 网关必须做协议翻译而非透传。
  • 上游 SSE 无 id: 行且 cache_key 一次性 → 无法真正的断线续传，只能网关侧缓冲重放。
  • 本站只有 单一 bot（provider 固定 DeepSeek）→ 只暴露 1 个诚实模型。

设计直觉：网关是「翻译层 + 可靠性层」。翻译层负责协议转换；可靠性层负责认证、熔断、缓存、限流。 两个原则贯穿始终：不伪造（上游没有的能力不假装支持）、不静默（任何丢弃/异常都要可观测）。

最深的一个修复（H1）

症状：中文/emoji 回复偶尔变成问号串。

根因：原实现逐网络 chunk 用 String::from_utf8_lossy 解码。 但 TCP chunk 边界是任意的，可能落在一个 UTF-8 码点中间 —— 半个码点被替换为 U+FFFD。

修复：改为字节级缓冲（Vec<u8>），只在完整事件边界解码。顺带修了 CRLF 分帧 + 8MB 上限。

反证：临时恢复旧实现，「漢字テスト😀」→「??????????」；修复后完整保留。这是唯一一个会造成静默内容损坏的缺陷。

最有技术含量的一个（v0.7.0 流式工具 hold-back）

模型输出 ```tool 块时，普通文本流会把这个原始 JSON 泄漏给客户端。 StreamToolFilter 状态机把工具块暂扣，且要处理 fence 标记被 delta 切断 的场景（三个反引号分三次到达）。

用「保守放行」策略：只有确定不在 fence 中才放行，避免泄漏。
