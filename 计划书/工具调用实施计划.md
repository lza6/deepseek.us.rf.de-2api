# 工具调用实施计划（v2.0.0 核心）

> 目标：让网关支持 **协议级** 工具调用 —— OpenAI `tools`/`tool_calls` 与 Anthropic `tool_use`/`tool_result`。
> 上游 AIPKit **不支持原生 function calling**（`分析文档/05` 实测 `allowTools=false`），
> 故采用**网关侧协议翻译**：注入工具说明 → 解析模型输出 → 产出协议级调用结构。

## 约束与设计原则

1. **不伪造**：上游没有原生 tool 协议，网关用文本约定 + 解析实现，但对外**产出标准协议结构**（真实可被客户端解析）。
2. **不破坏现有路径**：未传 `tools` 的请求行为完全不变。
3. **流式与非流式都支持**：非流式优先（简单正确），流式用 hold-back 策略。
4. **幂等**：工具调用解析失败（模型没按格式输出）时回退为纯文本，不报错。

## 数据流

```
客户端 (OpenAI tools) ──┐
                        ├─→ ToolDef[] ─→ 渲染工具说明 ─→ 注入 prompt ─→ 上游
客户端 (Anthropic tools)─┘

上游输出文本 ─→ 解析 ```tool 块 ─→ ToolInvocation[]
                                        │
       ┌────────────────────────────────┤
       ▼                                ▼
OpenAI: choices[0].message.tool_calls   Anthropic: content[].type=="tool_use"
        finish_reason:"tool_calls"                stop_reason:"tool_use"
```

## 工具说明格式（注入上游的约定）

```
You have access to tools. To call one, emit a fenced block:
```tool
{"name":"<name>","arguments":{...}}
```
Available tools:
- get_weather: 查询天气。参数: {"city": string}
- get_time: 当前时间。参数: {}
Only emit tool blocks when needed. Answer directly otherwise.
```

## 产出映射

| 中间表示 | OpenAI 输出 | Anthropic 输出 |
|---------|------------|---------------|
| `ToolInvocation{id,name,args}` | `{"id":"call_x","type":"function","function":{"name":..,"arguments":"<json>"}}` | `{"type":"tool_use","id":"toolu_x","name":..,"input":{...}}` |
| finish/stop | `finish_reason:"tool_calls"` | `stop_reason:"tool_use"` |

## 回传映射

| 客户端回传 | 转成 prompt 片段 |
|-----------|-----------------|
| OpenAI `role:"tool"`, `tool_call_id`, `content` | `[tool_result id=..] <content>` |
| Anthropic user 消息含 `tool_result` 块 | `[tool_result id=..] <content>` |

## 风险

- **模型不一定遵循格式**：解析失败则回退纯文本（不报错）。
- **流式 hold-back**：遇 ` ```tool ` 起始需暂扣后续 delta 直到闭合，增加状态机复杂度。
- **不破坏现有**：`tools` 为 None 时走原路径。
