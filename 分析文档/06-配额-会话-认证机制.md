# 06 · 配额、会话与认证机制

> 本文汇总 deepseek.es 的**身份、会话、配额、限流、安全**机制。
> 前端已还原的为 `静态确认`，服务端规则为 `待验证`。

---

## 1. 身份体系（三层）

| 层 | 标识 | 存储 | 生成方式 | 用途 |
|----|------|------|---------|------|
| 访客 | `aipkit_guest_uuid` | localStorage | `crypto.getRandomValues` UUID | `session_id`，会话归属 |
| 会话 | `aipkit_current_conversation_uuid` | sessionStorage | 客户端生成 | `conversation_uuid`，消息分组 |
| 消息 | `user_client_message_id` | 内存 | `aipkit-client-msg-<bot>-<ts>-<rand>` | 消息去重 |

### 1.1 访客 UUID 生成

```js
function generateGuestUuid() {
    return ("10000000-1000-4000-8000" + -1e11).replace(/[018]/g, e =>
        (e ^ crypto.getRandomValues(new Uint8Array(1))[0] & 15 >> e / 4).toString(16));
}
function ensureGuestUuid() {
    let e = localStorage.getItem("aipkit_guest_uuid");
    if (!e) { e = generateGuestUuid(); localStorage.setItem("aipkit_guest_uuid", e); }
    window.aipkit_guest_uuid = e;
    return e;
}
ensureGuestUuid();  // 页面加载即执行
```

### 1.2 客户端消息 ID 生成

```js
function generateClientMessageId(botId) {
    return `aipkit-client-msg-${String(botId || "default").replace(/[^a-zA-Z0-9_-]/g, "")}-${Date.now()}-${Math.random().toString(36).substring(2, 7)}`;
}
```

### 1.3 会话 UUID 再生

每次"新会话"（`enableSidebar` 模式或清空聊天后）调用 `aipkit_regenerateConversationUUID()`，
重置 `window.aipkit_current_conversation_uuid` 与 OpenAI 响应 ID。

## 2. 认证：WordPress Nonce

### 2.1 两套 nonce

| nonce | 来源 | 用途 |
|-------|------|------|
| `_ajax_nonce`（聊天） | `data-config.nonce` | AIPKit 所有 AJAX + SSE |
| `X-WP-Nonce`（dsgt） | `dsgtConfig.nonce` | dsgt REST（余额/订单） |

### 2.2 Nonce 刷新机制（自研补丁）

`aipkit-public-main-js-after` 包装了 `window.aipkit_frontendApiRequest` 和
`window.aipkit_chatUI_cacheSseMessage`，在遇到 nonce 错误时自动刷新重试：

```js
// 触发条件（错误消息包含以下任一，不区分大小写）：
//   "security check failed" | "session has expired" | "nonce"
// 刷新方式：
POST admin-ajax.php
  action=aipkit_get_frontend_chat_nonce
  bot_id=<id>
→ { success:true, data:{ nonce:"<new>" } }
// 更新 cfg.nonce 后重试原请求
```

### 2.3 Nonce 刷新端点

```
POST /wp-admin/admin-ajax.php
Content-Type: application/x-www-form-urlencoded  (FormData)
body: action=aipkit_get_frontend_chat_nonce&bot_id=<id>
→ { success: true, data: { nonce: "<新nonce>" } }
```

## 3. 配额模型（DEEPSEEK.DE 自研）

### 3.1 双轨制

```
┌──────────────────────────────────────────────┐
│ 每日免费额度 (free)   ← 优先消耗                │
│        ↓ 耗尽后                                │
│ 付费代币余额 (paid balance)  ← 购买获得         │
│        ↓ 耗尽后                                │
│ 配额耗尽 → quota_notice → 弹出购买             │
└──────────────────────────────────────────────┘
```

**证据**（`buy-tokens.js` 注释 + i18n）：
- i18n 明确写：`"los tokens gratuitos diarios se consumen siempre primero"`（每日免费 token 总是先消耗）
- 余额与浏览器绑定：`"el saldo está vinculado a este navegador"`（余额绑定此浏览器）

### 3.2 余额查询

```
GET /wp-json/dsgt/v1/balance?bot_id=<id>&_t=<ts>
Headers: X-WP-Nonce: <dsgtConfig.nonce>
→ { balance: <number>, free: { remaining: <number> } }
```

前端使用（`buy-tokens.js`）：
```js
var bal  = (typeof data.balance === "number") ? data.balance : 0;
var free = (data.free && typeof data.free.remaining === "number") ? data.free.remaining : null;

if (bal > 0 && free > 0)      // 双轨都可用 → "Modo gratuito activo · Saldo: X"
else if (bal > 0)             // 仅付费 → "Saldo de tokens: X"
else                          // 无余额 → 恢复原 footer
```

### 3.3 余额刷新时机

| 事件 | 触发 |
|------|------|
| 页面加载 | `tryUpdateFooterRepeatedly()` |
| 收到 AI 回复 | `aipkit:messageReceived` → 立即 + 400ms + 1500ms |
| 购买完成 | `dsgt:purchase-complete` |
| 配额错误 | `aipkit:messageError` → 注入购买 CTA |

> **关键**：`aipkit:messageReceived` 在流式回答完全写入后触发（SSE done + cache-sse-message 之后），
> 此时计费记录已入库，余额刷新才准确。

### 3.4 配额耗尽信号

当配额耗尽，SSE 返回 `error` 事件携带 `quota_notice`：

```json
{ "quota_notice": {
    "title": "...",
    "message": "... <a href=\"#dsgt-buy-tokens\">购买</a> ...",
    "actions": [{ "label": "Comprar tokens", "url": "...", "variant": "primary" }]
} }
```

前端在 `aipkit_chat_quota_message` 元素渲染，`buy-tokens.js` 监听并自动弹窗。

## 4. 限流与反滥用

| 机制 | 实现 | 状态 |
|------|------|------|
| Cloudflare Turnstile | `api.js` + 站点托管 | 待验证触发点 |
| WordPress nonce | `_ajax_nonce` | 静态确认 |
| 每日免费额度 | 服务端计数 | 待验证具体值 |
| 代币余额 | 服务端账本 | 静态确认 |
| IP 白名单（测试模式） | `admin_gated_msg` 提示 | 静态确认 |

### 4.1 Turnstile（Cloudflare 验证码）— ⭐ E2E 已还原完整机制

`api.js` 是标准 Cloudflare Turnstile 客户端脚本。站点在其上叠加了**自研安全层**（内联脚本 `deepseek-ts-js`）。

**完整机制**（E2E 还原）：

```
① 页面加载 → turnstile.render(widget, {sitekey, action:'chat'})
   sitekey = 0x4AAAAAADlLZ3ljqZP6cQwq   ← 真实值（从 HTML 提取）

② 用户发消息前，Turnstile 产出 token（managed 模式，需浏览器）

③ 前端 POST admin-ajax.php:
   action=deepseek_ts_verify&token=<turnstile_token>
   → {ok:true} + Set-Cookie: dsts_ok=1; dsts=<hash>

④ 后续聊天请求携带 dsts_ok cookie，服务端放行

⑤ 无 cookie / cookie 失效时，SSE 返回：
   event: error
   data: {"error":"Sicherheitspruefung erforderlich.","ts_required":true}
```

**前端自愈**（HTML 内联）：
- 拦截所有 fetch/XHR，遇 **403** 且 `code=deepseek_ts_required` / `ts_required` → `rearmAll()`
- 可见性变化 / 窗口聚焦 / 每 3.5h → `turnstile.reset()` 后台续期
- 静默 widget 常驻 DOM（`deepseek-ts-vh`）以便持续刷新 cookie

**Cookie 详情**：
| Cookie | 值 | 说明 |
|--------|-----|------|
| `dsts_ok` | `1` | 人类可读标记（前端据此判断已通过） |
| `dsts` | `<hash>` | 服务端校验凭证 |

**2API 应对**：集成 cf_solver 求解 Turnstile token → 调 `deepseek_ts_verify` 兑换 cookie → 缓存复用。详见 [07 文档](./07-2API代理实现指南.md) §4。

### 4.2 完整安全端点

| 端点 | 方法 | 参数 | 响应 | 状态 |
|------|------|------|------|------|
| `deepseek_ts_verify` | POST | `token`(Turnstile token) | `{ok:true/false}` + Set-Cookie | ✅ E2E 验证 |
| `deepseek_ts_required`(code) | — | — | 错误码（403 时） | 静态确认 |

### 4.2 IP 白名单

`dsgt-buy-js-before` 的 i18n 中有：
```
admin_gated_msg: "El modo de prueba está activo. Añade tu IP a la lista de permitidos en Ajustes → Guest Tokens..."
```
说明代币系统有"测试模式 + IP 白名单"，管理员可限制购买 widget 只对特定 IP 可见。

## 5. 计费与支付流程

```
① 用户点"购买 tokens" → 打开弹窗
② GET /packages → 渲染套餐列表
③ 选套餐 → PayPal Buttons.createOrder()
   → POST /create-order { package_key } → { order_id }
④ 用户在 PayPal 批准
⑤ onApprove → POST /capture-order { paypal_order_id }
   → { ok:true, balance:<新余额>, tokens_granted:<本次获得> }
⑥ 刷新余额、触发 dsgt:purchase-complete
```

**恢复购买**：
```
POST /resend-recovery { email, lang }
→ { success: true }   // 若该邮箱有购买记录，发恢复链接
```

**客服**：
```
POST /support { name, email, message }
→ { ok: true }
```

## 6. 会话历史（会话侧栏）

前端的"清空全部历史"逻辑（`deepseek-chat-button-ux-js-after`）揭示了会话 API：

```js
// 1. 列出会话
listRaw = await aipkit_frontendApiRequest("aipkit_get_conversations_list",
    { bot_id: botId, session_id: sessionId }, cfg);
const convs = (listRaw.data.conversations || listRaw.data.items) || [];
// 2. 逐个删除（注意 response shape 兼容）
for (const c of convs) {
    const uuid = c.conversation_uuid || c.uuid || c.id;
    await aipkit_frontendApiRequest("aipkit_delete_single_conversation",
        { bot_id: botId, conversation_uuid: uuid, session_id: sessionId }, cfg);
}
```

**推测响应结构**：
```json
// get_conversations_list
{ "success": true, "data": { "conversations": [
    { "conversation_uuid": "...", "title": "...", "created_at": "..." }
] } }

// delete_single_conversation
{ "success": true }
```

## 7. 安全边界（2API 代理需注意）

| 风险点 | 说明 | 代理对策 |
|--------|------|---------|
| cf_clearance 绑定 IP+UA+JA3 | CF 盾凭证不可跨环境回放 | 同 IP 同 UA 回放，见 07 文档 |
| Nonce 绑定会话 cookie | 需维持 WP cookie jar | 用持久 httpx Client |
| 访客身份绑浏览器 | 换 UUID 即换身份（可绕过单浏览器额度） | 代理侧固定/轮换 UUID |
| 免费额度按 IP/身份计 | 有滥用空间但违反 ToS | 遵守上游条款 |
| Turnstile | 高频触发需 token | 集成 cf_solver |

## 8. 会话隔离模型

```
访客 UUID (session_id)
   │
   ├─ 会话 A (conversation_uuid)
   │    ├─ 消息 1 (user_client_message_id)
   │    ├─ 消息 2
   │    └─ ...
   ├─ 会话 B
   └─ ...

每个会话携带：
   - OpenAI response ID 链（provider=OpenAI 时，实现多轮上下文）
   - 文件上下文（localStorage: aipkit_file_context_<conv_uuid>）
```

**多轮上下文实现**：
- 非 OpenAI provider：服务端按 `conversation_uuid` 查历史
- OpenAI provider：客户端传 `previous_openai_response_id` 衔接

**2API 意义**：代理需为每个下游会话维护一个 `conversation_uuid`（可映射 OpenAI 的 session id）。
