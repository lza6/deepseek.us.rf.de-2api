## 3. 验证 2：安全校验机制还原

从 HTML 提取到内联脚本 `deepseek-ts-js`（16482 字节），完整还原：

```js
var SITEKEY = '0x4AAAAAADlLZ3ljqZP6cQwq';
var AJAXURL = 'https://deepseek.es/wp-admin/admin-ajax.php';

// Turnstile 渲染（managed 模式）
window.turnstile.render(widget, {
    sitekey: SITEKEY, action: 'chat', theme: 'auto',
    callback: token => verifyOnServer(token, ...),
});

// 服务端兑换
fetch(AJAXURL, { method:'POST', body: 'action=deepseek_ts_verify&token=' + encodeURIComponent(token) })
  .then(r => r.json())
  .then(j => { if (j.ok) container.dataset.deepseekTsOk = '1'; });
```

**后端拦截逻辑**（HTML 内联，自愈 hook）：
```js
// 拦截 403，若 code/ts_required 命中则重新触发验证
if (resp.status === 403) {
    resp.clone().json().then(j => {
        if (j.code === 'deepseek_ts_required' || j.ts_required || (j.data && j.data.ts_required))
            rearmAll();
    });
}
```

**Marker Cookie**：`dsts_ok=1`（正则 `/(?:^|;\s*)dsts_ok=1(?:;|$)/`）
**续期**：可见性变化 / 窗口聚焦 / 每 3.5h 自动 `turnstile.reset()` 刷新

## 8. 验证 7：SSE 原始协议确认

**证据文件**：`抓包验证/evidence/sse_raw.txt`（4463 字节，真实响应原文）

```
event: message_start
data: {"message_id":"aipkit-msg-6ac45e8eb8c5a6.44139757"}

data: {"delta":""}

data: {"delta":"¡"}

data: {"delta":"Cl"}

data: {"delta":"aro! Aquí va"}

data: {"delta":":\n\n1..."}

data: {"delta":" 2... 3..."}

data: {"delta":" 🎉\n\n¿Ne"}

data: {"delta":"cesitas algo más?"}

data: {"delta":""}

event: done
data: {"finished":true}
```

**协议最终确认**：
| 事实 | 值 |
|------|-----|
| 分隔单位 | **空行**（`\n\n`） |
| `message_start` 帧 | `{"message_id":"aipkit-msg-<hex>.<hex>"}` |
| delta 帧 | `{"delta":"<文本片段>"}` |
| delta 事件名 | **无 `event:` 行** = SSE 默认 `message` 事件 |
| done 帧 | `{"finished":true}` |
| 首个 delta 可能为空串 | ✅ |
| 响应开头有填充（防缓冲） | 一个 `:` 注释行 + 大量空格 |

> ⚠️ **E2E 修正**：初版解析器错误地"沿用上一个 event 名"，把 delta 标成 `message_start`。
> 正确做法是**按空行分块**，无 `event:` 行的块视为默认 `message` 事件。
> 这正是真实 E2E 才能发现的坑（纯静态分析不会暴露）。
